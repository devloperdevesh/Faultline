
# Security Policy

## Reporting a Vulnerability

Faultline takes security vulnerabilities seriously. We appreciate responsible
disclosure and the efforts of security researchers to help keep the project
and its users safe.

**Please do not report security vulnerabilities through public GitHub issues,
pull requests, or discussions.**

### Preferred Reporting Method

If GitHub Private Vulnerability Reporting or GitHub Security Advisories is
enabled for this repository, please use the repository's private security
reporting feature.

If private reporting is unavailable, please contact the repository
maintainer privately through a verified contact method listed in the
repository or GitHub profile. Do not publish exploit details while waiting
for a response.

### What to Include

Please include as much of the following information as you can safely provide:

- A clear description of the vulnerability.
- The affected component, file, endpoint, or version.
- Steps to reproduce the issue.
- The potential security impact.
- Relevant logs, screenshots, or proof-of-concept code, if safe to share.
- Any suggested mitigation, if known.

Please keep reports concise and avoid sharing unnecessary sensitive data.

### Responsible Disclosure

- Allow maintainers reasonable time to investigate and address the issue
  before public disclosure.
- Do not exploit a vulnerability beyond what is necessary to demonstrate it.
- Do not access, modify, or disclose other users' data.
- Do not disrupt services or compromise systems that you do not own or have
  explicit permission to test.
- Coordinate public disclosure with the maintainers whenever possible.

### Protect Sensitive Information

Never include real credentials, API keys, access tokens, private keys,
production secrets, or private customer data in vulnerability reports,
issues, pull requests, or commits.

Use sanitized logs and minimal proof-of-concept examples wherever possible.

### Scope and Response

Reports concerning security weaknesses in Faultline's own code, dependencies,
configuration, or documented deployment process are welcome.

The maintainers will make reasonable efforts to acknowledge reports,
investigate the issue, assess its impact, and communicate any remediation
plans. Response and fix timelines may vary depending on severity,
reproducibility, and maintainer availability.

Please understand that Faultline is an open-source project and that a
specific response time or security fix cannot be guaranteed.

## Supported Versions

Until formal release and maintenance policies are established, please report
security issues affecting the latest code on the default branch.

## Questions

For non-sensitive questions about security practices, use GitHub Discussions
if enabled. Do not post vulnerability details publicly.
