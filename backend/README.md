
# Faultline Backend

The backend is responsible for the server-side workflows of Faultline, an
open-source security remediation platform.

Its intended responsibilities include processing security findings,
coordinating remediation workflows, managing verification jobs, and preserving
relevant results and evidence.

> **Development status:** This document describes the intended backend
> responsibilities. Available functionality depends on the current
> implementation.

## Responsibilities

- Validate incoming requests and application inputs.
- Process and normalize security findings from supported integrations.
- Coordinate remediation proposals and their review states.
- Manage verification jobs and record their outcomes.
- Persist relevant findings, job metadata, and verification evidence.
- Apply appropriate access controls and protect sensitive information.

Only capabilities implemented and tested in the current codebase should be
considered available.

## Prerequisites

Install the runtime and dependencies required by the backend's actual
implementation.

Check the repository files for the supported language version, dependency

## Getting Started

From the repository root:

```bash
git clone https://github.com/devloperdevesh/Faultline.git
cd Faultline/backend
```

Inspect the backend files and follow the installation instructions for the
dependency manager used by this project.

Create a local environment configuration from the project's example file,
if one is provided. Configure required values locally and never commit
credentials or production secrets.

## Testing

Run the test suite using the commands defined by the backend's actual
development configuration.

Tests should cover, where applicable:

- Request validation and error handling
- Finding normalization
- Workflow state transitions
- Verification result handling
- Authorization boundaries
- Sensitive-data redaction
- Malformed and oversized inputs

Record known limitations and avoid describing untested behavior as verified.

## Security Considerations

Treat repository contents, uploaded archives, dependency metadata, scanner
output, and generated remediation proposals as untrusted input.

Backend changes should follow the project's security requirements, including
input validation, safe process execution, appropriate resource limits, and
restricted execution of untrusted workloads.

See [../SECURITY.md](../SECURITY.md) and
[../THREAT_MODEL.md](../THREAT_MODEL.md).

## Development Guidelines

- Keep components modular and responsibilities clearly separated.
- Validate data at application boundaries.
- Handle errors explicitly and avoid leaking sensitive information.
- Add tests for new behavior and bug fixes.
- Update documentation when API contracts or configuration change.
- Do not claim a security control is implemented without supporting code
  and appropriate validation.
